# Формат CMN00 / 00000001.dat — боевые субтитры SRW V

Файл: `Data\BTLC\<LANG>\CMN00.CPK` → запись `00000001.dat` (CRI CPK, затем
слой XOR-шифрования SRWV — снимается `srwv_decrypt.py`). Всё little-endian.
Проверено на EN0 (1 331 776 байт) и JP0 (1 733 728 байт): структура и число
записей идентичны, различаются только тексты — т.е. игра адресует строки
по (секция, индекс), а не по смещениям, и длины строк свободные.

## Внешний контейнер (общий, тот же у 00000000.dat)

```
+0x00  u32  nSections        (00000001.dat: 6; 00000000.dat: 4)
+0x04  u32  fenceTableOffset (= 0x10)
+0x08  u32  dataBase         (= 0x30; начало данных секций)
+0x0C  u32  0
+fenceTableOffset:
       u32  fence[nSections+1]   — «заборные» смещения ОТНОСИТЕЛЬНО dataBase.
                                   fence[0] = 0; fence[i]..fence[i+1] — секция i;
                                   fence[nSections] = размер данных = EOF − dataBase.
далее нули до dataBase.
```

Секция i занимает абсолютные байты `[dataBase+fence[i], dataBase+fence[i+1])`.
Содержимое секции зависит от файла: в 00000001.dat каждая секция — таблица
строк (ниже); в 00000000.dat — бинарная разметка боёв (не строки).

## Секция-таблица строк (00000001.dat)

```
+0x00  u32  count
+0x04  u32  off[count]   — смещение каждой строки от начала пула;
                           off[0] = 0, строго возрастающие, строки лежат
                           ВПЛОТНУЮ: off[j+1] = off[j] + len(str[j]) + 1
                           (без дыр, без дедупликации повторов)
+0x04+4*count: пул — count null-terminated UTF-8 строк подряд
затем:  нулевое дополнение, чтобы конец секции был кратен 16
        (секции и весь файл выровнены по 16; dataBase+fence[i] всегда %16==0).
```

## Строки

- Кодировка UTF-8 (и в EN, и в JP — JP хранит каны/кандзи как UTF-8).
- Перенос строки в реплике — ЛИТЕРАЛЬНЫЕ два байта `5C 6E` («\» + «n»),
  НЕ символ 0x0A (в файле нет ни одного реального LF). В EN таких строк 1655.
- NUL внутри строки невозможен (терминатор).
- Пустых строк нет, но много заглушек `-` и `...` (178 строк длиной ≤1 байт).
- Максимальная длина реплики в EN — 147 байт; формат длину не ограничивает
  (ограничения только у рендера субтитров в игре — ширина плашки).

## Пересборка с другими длинами

Меняются: off[] внутри секции, паддинг секции, fence[] в заголовке, размер
файла. Число записей (count) менять НЕЛЬЗЯ — индексы = идентификаторы
(voice id для секции 5). Алгоритм: заново уложить строки вплотную,
пересчитать off, допаддить секцию до кратного 16, пересчитать fence
накопительно. Реализовано в `ru_cmn_subs.py`:

```
python ru_cmn_subs.py extract <in.dat> <out.json>
python ru_cmn_subs.py rebuild <in.dat> <translated.json> <out.dat>
```

JSON: `{"sections":[{"id","name","count","strings":[…]}]}` — идентификатор
строки = (id секции, позиция в strings). В JSON литеральный перенос виден
как `\\n` (два символа), реальных `\n` быть не должно.

Round-trip проверен: rebuild(extract(x)) == x байт-в-байт,
- EN0: sha256 0521d87a…5d2e089 ✓
- JP0: sha256 70cbc662…a2256f88 ✓

Замена строки на более длинную (25 → 87 байт UTF-8, кириллица + `\n`)
проверена: файл растёт на выровненную дельту, extract читает строку обратно,
все 6 count неизменны, прочие 34325 строк байт-идентичны, откат к
оригинальному тексту снова даёт исходный sha256.

После правки: зашифровать `srwv_encrypt.py`, упаковать обратно в CPK
(см. ru_cpk_patch*.py / ru_patch_cpk.ps1 — пайплайн как для других CPK).
В JP0-CPK запись 00000000.dat сжата CRILAYLA, 00000001.dat лежит raw.
