# Super Robot Wars V (PC) — формат файлов заставки Prologue.cpk

Относится к расшифрованным файлам `AIDDATA/<lang>/Prologue.cpk` →
`00000000.dat … 00000030.dat` (после cpk_extract.py + srwv_decrypt.py).
Формат проверен на всех 31 EN- и 31 JP-файлах (62/62 сошлись байт-в-байт
при round-trip). Инструмент: `ru_prologue.py` (extract / rebuild / test).

Все числа — little-endian. Текст — UTF-8 (и в JP-версии тоже),
так что русский UTF-8 кодировкой совместим.

## Общая схема

```
+0x00  заголовок, 24 байта
+0x18  record_count записей по (F + 30) байт каждая
```

Размер файла строго = `24 + record_count * (F + 30)`.

## Заголовок (24 байта)

| Смещ. | Тип | Значение | Описание |
|---|---|---|---|
| 0x00 | u16 | 24 / 37 / 47 / 1079 | `record_count` — число записей |
| 0x02 | u8  | 40…87 | **F** — размер текстового поля записи. Всегда = max(strlen) + 3 (строка + NUL + 2 запасных байта). У JP и EN версий одного файла F разный ⇒ игра читает F из заголовка, длина строк переменная |
| 0x03 | u8  | 9 / 2 / 1 / 0 | неизвестно (стиль/раскладка?). Совпадает у JP и EN, от текста не зависит |
| 0x04 | 6×u8 | EN: `28 38 28 5a 0c 50`, JP: `39 40 39 5a 0c 50`, титры: `24 24 24 2a 0c 40` | параметры отрисовки (размеры глифов/строк?). Различаются JP/EN, но от содержимого строк не зависят — при репаке копировать как есть |
| 0x0A | u16 | 0x78 (120) / 0xF0 (240) | тайминг (кадров на запись?) |
| 0x0C | u32 | 0 / 1 / 2 / 4 | неизвестно (id сцены/музыки?) |
| 0x10 | f32 | 1.0723 (титры: 1.9268) | масштаб/межсимвольный интервал |
| 0x14 | 2×u16 | 0,0 (титры: 720, 500) | доп. параметры (только в файле титров) |

При замене текста меняется ТОЛЬКО байт 0x02 (F); остальное копируется.

## Запись ((F + 30) байт), i-я запись по смещению 24 + i*(F+30)

| Смещ. | Размер | Описание |
|---|---|---|
| +0 | F | `text[F]` — NUL-терминированная строка UTF-8. **Байты после NUL — мусор** (несброшенный буфер инструмента упаковки), игра их игнорирует |
| +F | 30 | `meta[30]` — команды показа/тайминга. От текста не зависят: у JP и EN байт-в-байт совпадают при разных строках. При репаке копировать как есть |

### Семантика записей

Записи — это «тики» показа. Непустая строка = вывести новую строку текста
(печатается посимвольно движком, эффект «печатной машинки» — в рантайме,
в файле НЕ покадрово). Пустая строка (первый байт поля = 0x00) =
пустая строка / пауза; таких записей большинство.

### Откуда «обрезанный первый символ» и повторы строк

Это артефакт неверного фрейминга: если резать поток с шагом (F+30)
со смещения 0x19 (а не 0x18), первый символ каждой строки «уезжает»
в хвост предыдущей записи. Повторы — пустые записи, в мусоре которых
после ведущего NUL остался текст предыдущей строки (буфер упаковщика не
очищался). Встречающиеся `FF FF` на границе поля — такой же мусор:
в части файлов там `00 00` или обрезки строк.

### Метаданные (наблюдения, для перевода не нужны)

Нули почти везде; встречаются команды вида `63 00 05 00` (meta+8),
`01 02`, `02 02 11`, `0d … d2 00 80 00 80` (затемнение?), `b4 00` (пауза
180?), `94 02 10 00 78 00`. Копируются без изменений.

## Файлы

- `00000000–00000006, 00000008–00000030` — экраны наррации пролога
  (24–47 записей).
- `00000007` — титры (1079 записей, тот же формат; f3=0, свой float и
  параметры 720/500 в заголовке). EN- и JP-файл титров идентичны
  (одинаковый sha256).

## Замена текста другой длины

Можно: F пересчитывается как `max(len(utf8(строка))) + 3`, все записи
переупаковываются с новым F, размер файла меняется. Поля, которые
пришлось пересчитать: только `hdr[0x02]` (F) и, как следствие, общий
размер файла; meta и остальной заголовок копируются.

Ограничения:

1. **Жёсткое**: F — один байт ⇒ строка ≤ **252 байта UTF-8**
   (`max_text_bytes` в extract-JSON). rebuild падает с понятной ошибкой
   при превышении.
2. **Мягкое** (вне файла): ширина экрана. Оригинальные EN-строки —
   до ~60 видимых символов; русские строки разумно держать в тех же
   ~55–60 символах (это ~100–115 байт UTF-8 — в лимит 252 помещается
   с запасом). Покрытие кириллицы шрифтом игры надо проверить в игре.

## Инструмент

```
python ru_prologue.py extract <in.dat> <out.json>
python ru_prologue.py rebuild <in.dat> <translated.json> <out.dat>
python ru_prologue.py test <dir> [...dirs]
```

JSON: `lines[] = {idx, text}` — только непустые записи; `idx` не менять.
Гарантия: rebuild с неизменённым JSON даёт байт-в-байт исходный файл
(проверено на 62/62 файлах EN+JP). Демо смены длины: в `00000000.dat`
строка 37 байт заменена на русскую 100 байт → F 40→103, файл 1704→3216,
обратный extract возвращает текст без искажений, meta сохранены.

После rebuild файл нужно обратно зашифровать и упаковать в CPK
(обратные операции к srwv_decrypt.py / cpk_extract.py — отдельная задача).
